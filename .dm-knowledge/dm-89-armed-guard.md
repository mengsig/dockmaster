- **[invariant]** dm-command-guard.sh is ARMED (#89) via the project `.claude/settings.json` `hooks.PreToolUse` entry (matcher `Bash`), which resolves the script from `DM_HOME` else by walking up from `$PWD` — NOT `git rev-parse --show-toplevel`, because a managed clone/worktree toplevel has no `bin/`. Where no distro is above the cwd the hook exits 0: an unguardable session must not have every Bash call bricked. Editing that settings.json changes a SHA frozen in `config/runtime-performance-baseline.json`, so the baseline moves in the same commit.  _(2026-07-25T00:00:00Z)_
- **[invariant]** The guard classifies COMMAND POSITION vs ARGUMENT POSITION (#143). An option, or the value of the option before it, is data — a quoted sentence there is prose and is never re-entered, which is what makes `gh pr create --body "watch the git log for changes"` work. Still strict: a bare `git` token in any position, every argument of a command RUNNER (`is_command_runner`), and `sh -c` (classified earlier by `check_nested_shell`). The accepted narrowing is an unmodelled script running its own `--cmd "git push --force"` value. Do NOT "fix" that by re-entering option values again — it re-refuses ordinary PR bodies, and over-blocking is what gets a guard switched off.  _(2026-07-25T00:00:00Z)_
- **[convention]** `restore` and `checkout` are CONDITIONAL, not refused (#89): `git restore <path>` and `git checkout [<tree-ish>] -- <path>` pass when every operand is a scoped literal path, which is what unblocked the drifted-lockfile workflow that held the arming for two issues. `is_scoped_pathspec` refuses `.`/`..`/`/`, globs, and `:` pathspec magic; `require_static_args` refuses an operand the guard cannot read; a `checkout` without `--` moves HEAD and is refused.  _(2026-07-25T00:00:00Z)_
- **[pitfall]** Substitution content is captured by the LEXER, in both the plain and double-quoted states, and classified before segmentation (#138) — scanning the raw string instead would wrongly classify `'$(...)'` inside single quotes, which no shell executes. The capture helpers set the global `SUBSTITUTION_END` rather than printing it: a command substitution would run them in a subshell and lose both the token text and the recorded command, the same trap `git_subcommand_index` documents.  _(2026-07-25T00:00:00Z)_
