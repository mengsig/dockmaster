- **[decision]** The trash flow (bin/dm-trash.sh) is the THIRD terminal path, distinct from teardown (work landed) and dm-task.sh close (nothing built, refuses on any recorded local copy): built-but-discarded on the operator's word. It orchestrates only — dm-worktree.sh remove --force still owns deleting a worktree and parking its head, dm-pr.sh close owns the GitHub mutation, dm-task.sh/dm-backlog.sh own their records — so no second writer of any format appears.  _(2026-07-26T19:34:43Z)_
- **[invariant]** Trash orders its steps so no failure can strand state: record authority + snapshot -> close PR (reversible) -> force-remove the local copy (irreversible) -> terminal -> backlog -> archive. Every failing step STOPS the flow, and dm-task.sh state still reads truthfully at each stop (working while the local copy is there, discarded once it is gone). Its own pre-destruction status verb is 'trashed', which state reads through its unknown-verb fallback as working — correct for a trash that died mid-flow. A retry never degrades the snapshot: snapshot_value keeps a recorded head over a fresh 'none', because a failed forced removal leaves the worktree unreadable and the head IS the recovery key.  _(2026-07-26T19:35:06Z)_
- **[invariant]** A recovery claim is VERIFIED, never asserted: dm-lib owns the parked-ref layout (dm_discard_ref / dm_ref_component / dm_admin_worktree_head, moved out of dm-worktree.sh) and dm-trash.sh re-reads the ref out of the clone before printing committed_work=. Parking only WARNS when it fails, so an unverified claim would tell an operator work survived that did not. Uncommitted and untracked files are deliberately NOT snapshotted: git stash create cannot capture untracked files, so a partial snapshot would advertise recoverability it does not deliver.  _(2026-07-26T19:35:06Z)_
