A hold belongs to the id if its key starts with <id>-decision- OR its origin contains data/<id>/ (both filing conventions from the decision-hold skill). A hold key is unvalidated at creation, so a key can embed a newline; the jq extraction excludes any key containing "\n" ahead of the match, so a malformed multi-line key is never auto-resolved — it stays open by design, same fail-safe posture as the other gaps here.  _(2026-07-27T12:13:19Z)_
