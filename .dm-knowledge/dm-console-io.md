- **[invariant]** The console's own /review/<id>/ page is the PRIMARY destination for a review; the lavish session (4387) is a secondary 'the original' link. They are different things: the served page is the archived directory dm-lavish.sh list reports, the session is a separate server. Neither may be presented as the other - with no session open the secondary says so instead of redirecting to the archive.  _(2026-07-29T10:53:27Z)_
- **[decision]** A review page is NOT embedded in the console shell. Framing it would need frame-src on the console CSP AND would give crewmate-authored HTML same-origin scripted access to the operator's page (an iframe can call parent.fetch, whose CSP is the PARENT's connect-src 'self' - the review's own connect-src 'none' does not apply). The way back is instead a plain anchor the server appends after the served HTML; trailing content is reparsed into <body>, so position:fixed anchors it to the viewport whatever the page's markup does, and it needs no CSP change.  _(2026-07-29T10:53:27Z)_
- **[pitfall]** dm-backlog.sh hold is an upsert that PRESERVES an existing status/answer, so re-holding an answered key silently leaves it resolved. dm-ui.sh ask refuses a key that is already answered rather than posting a question with no panel holding it open.  _(2026-07-29T10:53:27Z)_
- **[convention]** dm-ui.sh ask <key> "<question>" [--options "A | B"] is how the dockmaster asks the operator through the page instead of the terminal: a decision hold (durable, rendered by the Needs-you panel) plus a transcript post. The answer returns on the ordinary poll queue as an operator message opening 'Answer — <question>'. No second transport, and the poll claim protocol is untouched.  _(2026-07-29T10:53:27Z)_
