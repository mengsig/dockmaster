- **[pitfall]** Claude Code Bash permission patterns: a bare trailing '*' after a space (e.g. 'rm -rf state *') enforces a word boundary (space or end-of-string); a '*' with no preceding space (e.g. 'rm -rf state*') matches with NO boundary, so it also matches 'state-backup' etc — safe over-match for a deny rule, dangerous for an allow rule. The ':*' suffix (e.g. 'pkill:*') is equivalent to a trailing ' *' but is ONLY recognized when it is the very last two characters of the whole pattern — a mid-pattern colon (e.g. 'git:* push') is a literal character and the rule never matches (this is exactly how the earlier global git deny rules went dead). Deny rules DO match past a leading env-var assignment ('FOO=bar rm -rf x' still hits 'Bash(rm -rf x*)'), and Claude Code splits a compound command on &&/||/;/|/|&/& before matching, so each subcommand is checked independently. None of this binds a command run as a subprocess of a bin/dm-*.sh script -- only a direct Bash tool call.  _(2026-07-30T05:14:28Z)_
